# LOCABLE 図面管理システム 操作マニュアル

このマニュアルは「locable-drawing-manager」の画面操作を説明するものです。
本システムは案件（プロジェクト）ごとに図面を管理し、各図面に必要な詳細度（LOD）の不足や、設計変更が図面に与える影響を可視化するためのツールです。

---

## 1. システム概要

### 1.1 何ができるか

- プロジェクトを「企画 → 基本設計 → 実施設計 → 施工図 → 竣工」というフェーズで管理する
- フェーズごとに、どの図面がどの詳細度（LOD）まで必要かを自動判定する
- 図面の「現在のLOD」と「必要なLOD」を比較し、**不足／OK／過剰／不要** を自動表示する
- 設計変更（チェンジオーダー）が、どの図面に影響するかを記録し、反映漏れを防ぐ
- ダッシュボードで、対応が必要な図面や変更を一覧で確認できる

### 1.2 画面構成

| 画面 | URL | 役割 |
|---|---|---|
| ダッシュボード | `/` | 全体の進捗・要対応事項のサマリー |
| 図面管理 | `/drawings` | プロジェクト・図面の作成・編集・一覧管理 |
| 変更項目 | `/changes` | 設計変更の登録と影響図面の管理 |
| 設定 | `/settings` | LODルール・図面種別・ステータスなどのマスター管理 |

画面上部のヘッダーから各画面へ移動できます。

### 1.3 用語

| 用語 | 説明 |
|---|---|
| **LOD（Level of Detail）** | 図面の密度（詳細度）。0（未着手）／1（簡易図面）／2（標準図面）／3（詳細図面）の数値で表し、簡易→標準→詳細の順に密度が上がるほどLODが高くなる。フェーズが進むほど高いLODが要求される |
| **必要性** | その図面がそのフェーズで「必須」「任意」「不要」かを示す |
| **LOD判定** | 「必要LOD」と「現在LOD」を比較した結果。下記参照 |
| **同期ステータス** | 変更項目が図面にどこまで反映されているかの状態 |

**LOD判定のルール：**

| 必要LOD | 現在LOD | 判定 |
|---|---|---|
| 0 | - | 不要 |
| > 0 | 現在 < 必要 | **不足**（対応が必要） |
| > 0 | 現在 = 必要 | OK |
| > 0 | 現在 > 必要 | 過剰 |

## 2. ログイン

本システムは Cloudflare Access による認証を使用します。社内のSSOアカウントでアクセスすると、許可されたメールアドレスのみ画面が表示されます。アクセスできない場合は管理者にCloudflare Accessの許可リストへの追加を依頼してください。

（ローカル開発環境では認証はスキップされます。）

現時点ではユーザーごとの権限区分（管理者／閲覧のみ等）はなく、ログインできた全員が全機能を操作できます。

## 3. ダッシュボード（`/`）

プロジェクト全体、または選択した1プロジェクトの状況をひと目で把握する画面です。

### 3.1 プロジェクト絞り込み

画面上部のプルダウンで「全プロジェクト」または個別プロジェクトを選択すると、以下の集計がそのプロジェクトに絞り込まれます。

### 3.2 進捗表示

- **全体進捗率**：承認済み図面の割合をプログレスバーで表示（ステータスごとの進捗(%)設定に基づく）
- **ステータス内訳**：「未着手」「作図中」「確認中」「承認済」などの件数
- **LOD分布**：未着手／簡易／標準／詳細の各密度に図面が何件あるかをグラフ表示
- **対応不要件数**：進捗計算の対象外（必要性「不要」）の図面数

### 3.3 サマリーカード（クリックで該当画面へ遷移）

| カード | 内容 | 遷移先 |
|---|---|---|
| 進行中プロジェクト数 | active状態のプロジェクト数 | - |
| LOD不足図面数 | 「不足」判定の図面数 | `/drawings?focus=lod_shortage` |
| 変更影響あり図面数 | 同期ステータスが「要確認」「未反映」の図面数 | `/changes?focus=alert` |
| 期限超過数 | レビュー期限・最終期限を過ぎた図面数 | `/drawings?focus=overdue` |
| ロック済み図面数 | 編集不可状態の図面数 | - |

### 3.4 「今日見るべき項目」

優先度の高い図面・変更が最大10件、優先度順に表示されます。LOD判定や変更影響の有無が一目で分かるため、日次の作業確認に使用します。

## 4. 図面管理（`/drawings`）

最も使用頻度の高い画面です。左：プロジェクト一覧、中央：図面一覧、右：図面詳細の3ペイン構成です。

### 4.1 プロジェクトの作成

1. 左ペイン下部の入力フォームでプロジェクト名と開始フェーズを入力
2. 作成ボタンを押すと、選択したフェーズのLODルールに基づき、初期図面一式が自動生成される

### 4.2 プロジェクトのライフサイクル操作（左ペイン）

選択中のプロジェクトに対して以下の操作ができます。

| 操作 | ボタン表記 | 動作 |
|---|---|---|
| フェーズを進める | `次のフェーズへ進む（◯◯）` | 現在フェーズを更新し、全図面のLOD要件を再評価。新フェーズで必須の図面が無ければ自動追加 |
| フェーズを戻す | `前のフェーズへ戻る（◯◯）` | 同様にLOD要件を前フェーズの基準で再評価 |
| プロジェクトを完了 | `✓ 完了にする` | `project_status` を `completed` に変更。完了後に書き出しが可能になる |
| 書き出し | `書き出し` | プロジェクト概要・図面一覧・変更項目・LODステータスなどをファイル出力。完了後、Google Driveの `99_Archive` フォルダへ保存するよう案内メッセージが出る |
| アーカイブ | `アーカイブする` | プロジェクトを非表示化（一覧・ダッシュボード集計から除外） |
| アーカイブ取消 | `アーカイブを取り消す` | 完了状態に復元 |

> 注意：フェーズ変更・アーカイブは図面のLODや必要性に一括で影響するため、実行前に内容を確認してください。元に戻す操作（前フェーズへ戻る／アーカイブ取消）はありますが、変更履歴は監査ログに残るのみで自動ロールバックはされません。

### 4.3 図面一覧（中央ペイン）

#### 検索・フィルター

- テキスト検索：図面番号・図面名で絞り込み
- LOD判定：不足／OK／過剰／不要／すべて
- 必要性：必須／任意／不要／すべて
- ステータス、図面種別（設定画面で登録した選択肢から選べる）

#### 表示切替

- **リスト表示**：表形式。列見出しクリックでソート可能。行内でステータス・種別をその場で変更できる
- **カード表示**：カード形式の一覧

#### 作業キュー

画面上部に「未着手」「要確認」「期限あり」の件数バッジが表示され、対応漏れの早期発見に使えます。

#### 図面の新規登録（2つの方法）

**① 個別入力**
1. `+ 図面を追加` をクリック
2. 図面番号・図面名・種別・必要性・ステータスを入力して保存

**② CSVインポート（複数件まとめて登録）**
1. `テンプレートDL` でCSVテンプレートをダウンロード
2. Excel等でテンプレートに図面情報を入力して保存
3. `CSVインポート` ボタンからファイルを選択
4. 行ごとに検証され、成功件数・エラー件数が表示される（エラー行は登録されない）

#### ページネーション

1ページあたり 20／50／100件 を切り替え可能。

### 4.4 図面詳細（右ペイン）

一覧で図面をクリックすると右ペインに詳細が表示され、その場で編集できます。

編集可能な項目：

- 図面種別、必要性、必要LOD、現在LOD（現在LODを変更するとLOD判定が即時に再計算される）
- ステータス、ロック状態（設定画面のロック状態管理に準拠）、承認ステータス
- 担当者（assignee）
- レビュー期限・最終期限
- Google Drive リンク（PDF用・ソースファイル用）
- バージョン、優先度スコア、メモ
- この図面に関連する変更項目の一覧表示（変更影響の確認用）

> ファイル本体はGoogle Driveに保存し、本システムにはURLのみ登録します。アップロード機能はないため、Google Drive側で共有設定を行ってからURLを貼り付けてください。

## 5. 変更項目管理（`/changes`）

設計変更（チェンジオーダー）を記録し、関連する図面への反映状況を追跡する画面です。

### 5.1 プロジェクトの選択

画面上部のプルダウンで対象プロジェクトを選びます。

### 5.2 変更項目の登録

1. フォームに「変更理由」「変更内容」を入力
2. 「影響度」を 高／中／低 から選択
3. `追加` ボタンで登録（初期ステータスは「未確認」）

### 5.3 変更項目のステータス管理

一覧テーブルで各変更項目のステータスを変更できます：
`未確認 → 確認中 → 承認済 → 反映中 → 対応済`（または `却下`）

### 5.4 影響図面のリンク

設計変更がどの図面に影響するかを明示的に紐付けます。

1. 「変更項目」「図面」のプルダウンを選択
2. 影響度（高／中／低）を選択
3. `リンク追加` をクリック

リンクされた図面は `has_change_alert` フラグが立ち、ダッシュボードの「変更影響あり図面数」に反映されます。

### 5.5 同期ステータスの更新

リンクされた各図面について、対応の進み具合を以下の5段階で管理します。

| 同期ステータス | 意味 | ダッシュボード警告対象 |
|---|---|---|
| 未確認 | 影響の有無を未判断 | - |
| 要確認 | 影響評価中 | ○ |
| 未反映 | 変更が図面にまだ反映されていない | ○ |
| 反映済 | 変更を図面に反映済み | - |
| 対象外 | 結果的に影響なしと判断 | - |

一覧の行にあるドロップダウンから直接変更できます。設計変更が発生したら、関連図面をすべてリンクし、反映が完了するまで「未反映」のまま運用するのが基本フローです。

### 5.6 フォーカス表示

ダッシュボードから `?focus=alert` 付きで遷移すると、変更影響のある項目のみに絞った表示になります。

## 6. 設定（`/settings`）

マスターデータを管理する画面です。タブで4種類の設定を切り替えます。

### 6.1 LODルール

「フェーズ × 図面種別」ごとに、必要LODと必要性（必須／任意／不要）を定義します。

- 行の追加・削除・編集が可能
- ここで設定した内容が、プロジェクト作成時の初期図面生成と、フェーズ進行時の再評価の基準になる
- 変更すると既存プロジェクトには即座に反映されない点に注意（再評価は「次／前のフェーズへ」操作時に実行される）

### 6.2 図面種別管理

「全体平面図」「展開図」「天井伏図」「仕上表」など、図面の種別選択肢を管理します。並び順も指定できます。

### 6.3 図面ステータス管理

「未着手」「作図中」「確認中」「承認済」などのステータス選択肢を管理します。各ステータスに **進捗(%)** を設定でき、これがダッシュボードの全体進捗率計算に使われます。

### 6.4 ロック状態管理

「編集可」「フェーズロック」「承認ロック」「施工ロック」「竣工ロック」など、図面のロック状態選択肢を管理します。図面詳細の編集画面で選択肢として表示されます。

> 設定変更はプロジェクト横断で共有されるマスターデータです。既存図面に割り当てられている種別・ステータス名を削除すると表示に不整合が出る可能性があるため、削除前に使用箇所がないか確認してください。

## 7. よく使う操作フロー

### 7.1 新規プロジェクトを立ち上げる

1. `/drawings` でプロジェクト名・開始フェーズを入力して作成
2. 自動生成された初期図面一覧を確認
3. 必要に応じて `+ 図面を追加` や CSVインポートで図面を追加
4. 各図面の担当者・期限・Google Driveリンクを入力

### 7.2 フェーズを進める

1. 現在フェーズの図面が一通り「承認済」になっていることをダッシュボードで確認
2. `/drawings` の左ペインで `次のフェーズへ進む` を実行
3. 新フェーズで必要LODが上がった図面や、新規に必須となった図面を確認し、対応を割り振る

### 7.3 設計変更が発生したとき

1. `/changes` で変更項目を登録（変更理由・内容・影響度）
2. 影響する図面をすべてリンク追加
3. 各図面担当者が反映作業を行ったら、同期ステータスを「未反映」→「反映済」に更新
4. ダッシュボードで「変更影響あり図面数」が減っていくことを確認

### 7.4 プロジェクトを完了・保管する

1. `/drawings` で全図面のLOD判定・ステータスが完了水準であることを確認
2. `✓ 完了にする` を実行
3. `書き出し` を実行し、出力されたファイルをGoogle Driveの `99_Archive` フォルダへ保存
4. `アーカイブする` を実行してプロジェクト一覧・ダッシュボードから除外

## 8. トラブルシューティング

| 症状 | 確認事項 |
|---|---|
| 画面にログインできない | Cloudflare Accessの許可リストに自分のメールアドレスが登録されているか管理者に確認 |
| CSVインポートでエラーになる行がある | テンプレートの列名・必須項目（図面番号・図面名等）が正しく入力されているか確認 |
| フェーズを進めても図面のLODが変わらない | `/settings` のLODルールに、対象フェーズ×図面種別の組み合わせが登録されているか確認 |
| 変更項目をリンクしたのにダッシュボードに警告が出ない | 同期ステータスが「未確認」「反映済」「対象外」になっていないか確認（警告対象は「要確認」「未反映」のみ） |
| 種別・ステータスの選択肢が表示されない | `/settings` の該当タブでマスターデータが登録されているか確認 |

## 9. 開発者向け補足

開発・デプロイ手順の詳細は [README.md](../README.md) を参照してください。概要は以下の通りです。

- フロントエンド：Vite + React 19 + TypeScript（`src/`）
- API：Cloudflare Pages Functions（`functions/api/`）
- DB：Cloudflare D1（`migrations/`）
- 起動：`npm install` → `npm run dev`
- DBマイグレーション：`npm run db:migrate:dev` / `db:migrate:remote:dev` / `db:migrate:remote:prod`
